# LocalQL v1 Release Notes

LocalQL v1 provides a local structured-source workflow backed by DuckDB SQL.
Install the `localql` package and use the `csvql` command.

## 1.2.0

LocalQL 1.2.0 turns the CSV-first source foundation into one deterministic
workflow for local CSV, Parquet, JSON, NDJSON, and Excel data. Each supported
format exposes relational data to DuckDB, so one query can join sources across
all five providers.

Source selection is deliberately predictable. An explicit type always wins, a
recognized file extension selects its provider, and an extensionless or
otherwise ambiguous source receives bounded read-only identification. LocalQL
reports the candidate evidence and required next action, but never silently
guesses between formats. Directories are always explicit; a partitioned Parquet
dataset therefore requires `--type parquet` or saved catalog intent, and LocalQL
does not recursively discover mixed datasets.

Provider options are shared across the CLI, LocalQL Workbench, version 2 project
catalogs, and the Python API. Parquet supports explicit partitioning and
name-based schema union. JSON and NDJSON support bounded inference, explicit
scalar schemas, and fixed record paths. Excel supports exact worksheet and A1
range selection, header and empty-row controls, and text or inferred type
conversion.

Existing version 1 `.csvql.yml` catalogs remain readable. New catalog writes
store normalized source definitions, including explicit provider intent and
options. Multi-source CLI commands use `--source`, `--source-type`, and
`--source-option`; the existing CSV-compatible `--table` path remains available.
The `csvql` command, `csvql` Python import package, and small
`CSVQLSession`/`SourceDefinition` Python API remain compatible.

Inspect, sample, and profile operations now use the same provider workflow, and
cross-format joins behave like ordinary relational queries. The optional
terminal interface is now presented as **LocalQL Workbench**. Its help explains
the deterministic detection rules, and its error panel preserves readable
multiline diagnostics and suggestions while escaping terminal control
characters.

Complete query results can now be written as NDJSON, Parquet, or Excel from the
CLI, Python API, and Workbench. NDJSON is one object per row; the existing JSON
format remains the LocalQL metadata envelope. Parquet preserves DuckDB logical
column types and is the preferred round-trip format. Excel produces an `.xlsx`
workbook for spreadsheet interchange and follows DuckDB Excel writer
conversions.

Excel uses DuckDB's optional `excel` extension. Provision it explicitly in the
same Python environment before opening or exporting a workbook. LocalQL never
installs an extension while starting, detecting, querying, or exporting;
missing availability produces an actionable diagnostic instead.

The repository includes a reproducible end-to-end benchmark matrix for CSV,
JSON, NDJSON, Parquet, and Excel sources crossed with NDJSON, Parquet, and Excel
outputs. Its artifacts record the exact runtime, input and output sizes,
timings, throughput, and post-timing correctness checks; benchmark results are
local evidence rather than universal performance claims. See the
[LocalQL v1.2.0 benchmark snapshot](../benchmarks.md) for the published matrix,
environment, interpretation guidance, and reproduction path.

The provider registry and lazy factory are internal extension boundaries, not a
public plugin SDK. LocalQL 1.2.0 remains a local engineering tool: it does not
add remote databases, cloud or object-store connectors, credential handling,
recursive directory guessing, or silent dependency installation. LocalQL still
executes trusted local DuckDB SQL and does not sandbox DuckDB or restrict
filesystem access.

## 1.1.1

LocalQL 1.1.1 carries the complete v1.1 feature set forward from the
validation-only `v1.1.0` tag. Version 1.1.0 was not published to PyPI or as a
GitHub Release, so 1.1.1 is the first public release of this behavior. Product
behavior is unchanged from that qualified tree; 1.1.1 finalizes the public
release metadata and adds a release-state audit that rejects non-final
documentation before artifacts are built.

Interactive `csvql query` and `csvql run` table output now keeps a bounded
preview of 1,000 rows by default, while query/run JSON output and Python API
results remain complete. CLI exports and terminal-menu export/save actions use
complete results instead of inheriting the preview bound.

The terminal menu retains bounded previews while preserving complete results
under one 1 GiB session capacity with no automatic eviction. Existing preserved
results stay available if that capacity is exhausted; a new result then reports
a preview-only state and cannot be fully exported or saved. Delete an older
preserved result from History and rerun the query when you want to reclaim
capacity for a new complete result.

The terminal menu now supports source-free DuckDB SQL before a CSV is loaded.
Active-result and History actions stay attached to the result selected or
recalled, so export and save target the result shown in Results.

CSV access now runs through private `SourceSpec` and `SourceAdapter` contracts.
This is a CSV-first internal foundation for later source work, not a public
plugin API or support for additional formats.

If a script previously parsed human-readable table output and expected every
row, switch it to query/run `--output json` or `csvql export`. Those complete
result surfaces do not inherit the interactive table-preview bound.

## 1.0.0

### Highlights

- Query one CSV directly or join named CSV tables.
- Save a repeatable project catalog in `.csvql.yml`.
- Run saved SQL and export results as CSV, JSON, Markdown, or text.
- Inspect, sample, and profile sources, and run configured data-quality checks.
- Use `csvql menu` as an optional terminal workbench.

### Core CLI and optional terminal menu

The core `csvql` command is installed with `localql`. The terminal menu is an
optional extra installed with `localql[tui]`. It provides a source list, SQL
editor, results, and session history; the same CSV sources and SQL safety rules
apply to both interfaces.

`F4` or `Ctrl+R` runs selected SQL or the current statement. `F12` or
`Ctrl+B` runs a semicolon-delimited buffer. See the
[Terminal menu guide](../tui-guide.md) for the full key reference.

### Compatibility and safety

LocalQL supports Python 3.11 through 3.14 on macOS, Linux, and Windows.

LocalQL executes trusted local DuckDB SQL. It does not sandbox DuckDB or
restrict filesystem access. Run only SQL you trust.
